# SeedoMac 小屏布局、独立窗口与快捷键修复

日期：2026-09-18

## 根因与修复

### 小屏休息页

- 原休息页把图标、说明、应用列表、输入区和全部按钮放在不可滚动的 VStack 内，另加上下各 60pt padding；“暂停专注追踪”排在最底部，在较低的逻辑分辨率下超出屏幕。
- 内容改为可滚动区域，休息操作与暂停按钮固定在滚动区外。暂停在小结和倒计时两种状态均可操作。
- Esc 仅在小结页且允许延期时生效；⌘Return 开始休息，⌘P 暂停追踪。
- 覆盖层按各显示器原始 frame 展示，不再调用 center()；窗口关闭后不自动释放，配合控制器统一管理。

### 手动记录、设置独立展示

- 手动记录原先必须打开统计主窗口，再通知 StatsView 展示 sheet。通知触发的预填还发生在 sheet 创建前，可能丢失。
- 改为 AppDelegate 统一接收手动记录请求，创建独立 ManualRecordWindowController；菜单、统计页按钮和提醒通知走同一路径，不依赖主窗口存在。
- 设置或手动记录展示时隐藏主窗口；窗口间切换使用 orderOut，避免清空手动记录草稿。手动窗口关闭后释放控制器，下次创建新表单。
- 禁止独立窗口自动合并为系统标签页。设置去除固定 450×600 内容尺寸，允许内容随窗口缩放。
- 手动记录通过构造参数传入时长与开始日期，跨午夜时日期同步回退；字段可滚动，分类自动换行，保存/取消固定在底部。
- 保存保持后台写库，完成后回到主线程；成功才关闭和广播刷新，失败保留表单并显示错误。保存中禁用重复提交及关闭。
- 手动输入的时长也须验证 1–1440 分钟，不能只依赖 Stepper 的范围。预填对非有限数防护，并限制到单条记录的时长范围。

### 快捷键

| 场景 | 快捷键 |
| --- | --- |
| 应用内手动记录 | ⌘N |
| 应用内设置 | ⌘, |
| 应用内开始/暂停 | ⌘P |
| 应用内切换纯专注 | ⌘D |
| 应用内详细统计 | ⇧⌘S |
| 设置保存 | ⌘S |
| 手动记录保存/取消 | ⌘Return / Esc |

- 全局快捷键保留原有用户配置，并新增可配置的手动记录、统计入口；不强行占用系统级默认组合。
- 全局动作改为按键释放时触发，避免长按重复切换；纯专注入口真正支持开/关。
- 休息覆盖层可见时，全局暂停同时结束覆盖层状态，避免仅改 isTracking 而留下遮罩。

## 本次审查发现、未扩大范围修复的问题

1. **P1 — 离席记录起止相同**：AppDelegate.handleAFKThresholdReached 先将 currentSessionStartMs 赋值为 endTs，再读取它作为 startTs，导致传给离席表单的区间为零。需要先确定离席弹窗应记录“此前工作”还是“离席时长”，再保存正确的原始边界。
2. **P2 — 多屏休息状态不共享**：BreakOverlayWindowController 为每块屏幕构造独立 BreakOverlayView，而 state、timer、hasFinished 都是视图本地状态。在一块屏幕开始休息，其他屏幕仍停留在小结；应迁移为控制器持有的共享会话状态。
3. **P2 — 结束并记录取消不回滚**：stopAndRecord 在表单保存前清零计时；取消表单不会恢复。本次仅移除延迟通知、确保预填可靠，并防止已有草稿时再次清零。完整修复需要明确取消语义与恢复追踪的事务边界。
4. **P2 — 自动测试入口缺失/宿主过期**：需要补充共享测试 scheme，并将 TEST_HOST 与当前产品名保持一致；本次只记录，不改动用户现有发布配置。

## 经验

- 小屏适配的关键是把必达操作移出可溢出的内容区，而不是仅缩小字号或整体缩放。
- 跨视图传参使用初始化数据或共享模型，不向尚未创建的视图发送一次性预填通知。
- 独立窗口入口应由应用层管理，不能绑定在某个主视图的生命周期上。
- 保存成功、界面关闭、刷新统计应形成明确的顺序；异步失败必须保留用户输入。
