# SeedoMac UI 重整与休息页自然布局

日期：2026-09-19

## 问题与当前约定

休息提醒页把今日目标放在顶部、操作区固定在底边，导致信息层级倒置，纵向屏幕留下大片空隙；半透明黑色背景还会透出底层应用文字。统计页固定 380 点右栏挤压小窗口内容。

Fisher 明确要求解除底部固定、目标下移并优化其他 UI。因此本记录取代此前「提醒页底部操作区布局」的固定栏方案，以及「倒计时居中」文档中为固定底栏预留空间的约定。

## 实现

- `BreakOverlayView` 使用一个 ScrollView，提示、活动回顾、目标、按钮按正常文档顺序排列；不使用底部 safeAreaInset。内容短时整体居中，内容长时可滚动到底。
- 内容最大宽 860 点；可用宽度达到 720 点时活动概览与回顾表单并排，否则竖排。今日目标始终位于回顾下方。
- 背景始终先绘制不透明底色，默认使用深墨绿色；自定义图片或颜色增加深色遮罩，确保文字对比度。休息与纯专注界面明确采用 dark 配色。
- 新增 `SeedoStyle`，集中维护随明暗模式变化的背景、表面、青绿色强调色，以及卡片、输入框、按钮、分类选择和页标题组件。
- 统一菜单栏、目标编辑、今日任务、执行力教练、统计、设置、手动记录、记录编辑、离席返回、AI 复盘与纯专注界面的相关样式。
- 统计页按 900 / 760 点分段布局，最窄窗口所有统计块竖排。离席返回和纯专注记录表单允许滚动。
- 应用时长文案改为准确的「本轮活动」，不足一分钟显示 `< 1 分钟`。保留原本的计时、保存和快捷键回调。

## 验证

- Xcode Debug 与 Release 完整构建通过。
- 现有 macOS 测试目标全部通过：20 tests、0 failures。
- 使用真实 SwiftUI 视图源码和独立内存 fixture 服务渲染 1100×850、802×1071、600×700 休息页；600×700 实际滚动到底，目标和所有按钮完整可见。
- 使用同一源码的预览副本切换初始阶段，渲染 800×600 倒计时布局。
- 渲染程序没有打开真实数据库、调用 AI 或启动活动追踪。截图为示例数据，保存在 `docs/ui-refresh/`。
- XCTest 宿主运行时会初始化 AppDelegate，因此出现系统快捷指令服务不可用等测试环境日志；所有测试仍正常完成。界面本身另以独立 fixture 渲染验证，不读取用户数据库。

## 经验

固定底栏不是保证操作可达的唯一方案。对全屏休息页，更重要的是合理限制内容宽度、分清视觉层级、提供自然滚动，并用实际渲染检查内容底部。全屏隐私遮挡应先画不透明底色，不能依赖深色文字或半透明覆盖层。

## 部署排查

如果源码和工作区构建已经是新版，但截图仍出现顶部目标、居中大图标和底部固定栏，应先检查实际启动路径。2026-09-21 发现 `/Applications/Seedo.app` 仍是 2026-09-19 20:24 的旧二进制；之前只完成了工作区 Release 构建，没有覆盖安装应用。重新运行 `build_dmg.sh` 后，将 `build/Export/Seedo.app` 同步到 `/Applications/Seedo.app`，并验证两个二进制 SHA-256 相同、代码签名通过。替换后需退出旧进程并重新打开应用，当前运行中的旧进程不会因为 bundle 被替换而自动变成新版。
